La cause est en amont (`docs/tickets/09-ya03-base.md`, points ouverts).

Correctif : commit `fe3dbfa25`, avec des tests sur des cas réels de ce run (`bench/smoke/tests/fixtures/ya03-ab1-echecs.jsonl`). Les échecs se lisent désormais ainsi :
- **`python_repl`** : dans `details.status` ;

- **`edit()`** : compté seulement si l'exception est levée par le skill (sa frame figure dans le traceback).

## Bras `kernel` contre la baseline (filet de régression, pas un verdict)

**Méthode** : le plan prévoyait `compare.py`, mais cet outil ne prend qu'un `report.json` de chaque côté et le banc n'a pas d'outil qui fusionne 30 bras. La comparaison est donc refaite dans `ya03-ab1-20261114-mesures.py`, avec les seuils de `compare.py` (`compare.py:136-159`), en alerte dans les deux sens :
- **par tâche** : 2 × le CV de la tâche dans la baseline, au moins 5 % ;
- **pour l'agrégat** : 2 × `aggregate.cv` ;
- **côté baseline** : coût rapporté (`baseline.py`) ;
- **côté B** : les 3 bras `kernel` de chaque tâche ;
- **version des tâches** : identique à la baseline pour les 10.

**Résultats** :
- **Résolution** : aucune régression, les 8 tâches stables sont à 3/3.
- **Coût agrégé des tâches stables** (rapporté) : 0,3953 → 0,3434 $, soit **−13,1 %** pour un seuil de ±12,1 %. C'est une baisse.
- **Alertes par tâche** :
  - `node-tough-cookie-630` : coût −34,1 % (seuil 13,4 %) ;
  - `py-langextract-584` : coût −26,0 % (seuil 24,2 %) ;
  - `node-koa-2029` : tokens +36,7 % (seuil 19,1 %), avec un coût en baisse de 25,3 %.

**Réserve du plan** : la comparaison n'est pas entrelacée. La baseline vient des 30 bras B de l'A/B `rlm.spawn` du 12/11, binaire `69cc894`, `rlmMaxDepth` à 0. Le bras `kernel` tourne sur le binaire `80e20ea`, qui ajoute la PR 1 de YA-03 (`read()`, `bash(env=)`, note de troncature), le rejeu des appels libres (#28) et les correctifs de flux (#30). Une partie de l'écart peut venir de la date et du backend. Les alertes servent de filet et ne changent pas le verdict.

## Limites

- **Résolution** : 24 contre 24 sur 30 paires. Le seuil de 3 tâches est une règle de décision, pas un test statistique. Les échecs portent sur les deux tâches non stables, dans les deux bras.
- **Bootstrap sur les tâches** : les 10 tâches (dont 8 stables) sont tenues pour échangeables, et la variance entre passes n'y est pas propagée.
- **Coût théorique** : il applique les tarifs API (`prices.json`, version 2026-11-04) aux tokens du backend d'abonnement.
- **Une seule famille de modèles**, et des tâches courtes (5 à 23 tours en moyenne).
