## Limites

- **Un seul réglage, deux effets** : `rlmMaxDepth` 0 coupe la capacité de lancer des sous-agents et raccourcit le prompt (environ -1 020 tokens, estimation) ; l'A/B mesure les deux ensemble, comme prévu par le plan. La part du prompt seul n'est pas isolée.
- **Tâches courtes** : 16.7 à 37.7 tours moyens de la session principale par tâche dans le bras A. Le banc a peu de tâches longues, celles où l'isolement du contexte par des sous-agents pourrait payer. Le verdict vaut pour ce banc.
- **Résolution** : 25 contre 25 sur 30 paires ; le seuil de 3 est une règle de décision, pas un test. Les échecs portent sur les deux tâches non stables, dans les deux bras.
- **Tâches stables** : définies par la baseline de `main`, mesurée avec `rlm.spawn` actif. La nouvelle baseline sur la config retenue est l'étape suivante du plan.
- **Coût théorique** : tarifs API (`prices.json`, version 2026-11-04) appliqués aux tokens du backend d'abonnement. `cacheWrite` toujours à 0 côté Codex : d'où le coût pessimiste.
- **Bootstrap sur les tâches** : 10 tâches (8 stables) tenues pour échangeables ; la variance entre passes d'une même tâche n'y est pas propagée. Bruit de la baseline entre passes : CV 0.167 sur le coût des tâches stables, loin des écarts observés.
- **Masquage** : son verdict du 06/11 (rejeté) valait pour `rlm.spawn` actif et devait être rejugé après la décision sur `rlm` (`masquage-20261106.md`). Non fait ici.
